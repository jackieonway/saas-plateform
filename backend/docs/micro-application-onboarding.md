# 微应用简易接入

应用管理使用连续接入面板完成版本发布、就绪检查和访问范围配置。普通独立前端采用 HTML 入口与 iframe 隔离，已按平台 SDK 契约接入的 React、Vue 或其他框架构建结果均可按此方式登记。本次新增就绪和追加授权接口，前后端需同步发布。

## 创建应用

在“应用管理”点击“新建微应用”，填写名称和编码。默认自动生成 `/micro/{code}` 路径及首页菜单，创建后直接进入发布步骤。图标、描述、排序、状态、自定义路径和第一方模块选择位于“更多设置”。

应用编码创建后不可修改。第一方 ESM 应从当前宿主实际包含的模块中选择，编码和入口自动匹配；该模式与宿主共享执行环境，模块须事先经过审核并纳入宿主构建，代码更新随宿主发布。

## 选择版本来源

普通发布有两种方式，每次只展示当前方式需要的字段：

| 来源 | 需要提供 | 系统处理 |
| --- | --- | --- |
| 上传构建包（默认） | 版本号、ZIP 或 tar.gz | 读取包内入口与资源，生成固定版本地址，按交付配置预检或等待节点分发 |
| 已部署地址 | 版本号、HTML 入口 URL | 登记版本并自动执行预检，发现 HTML 引用的脚本、样式、modulepreload 等资源 |

**普通 URL 发布不用填写 JS/CSS 地址列表。** 例如版本号为 `1.0.0`，入口可使用 `/sub-apps/crm/versions/1.0.0/index.html`，或已批准来源的绝对 HTTPS 地址。入口路径必须包含相同的固定版本目录，资源应使用可正确解析的相对路径。

“补充检查项（可选）”仅用于额外健康地址，或 HTML 未直接引用的动态资源。服务端分析 HTML 不会运行任意业务 JavaScript，因此无法穷举运行时计算出的 import、接口返回的资源地址等。上传构建包会检查包内完整资源清单；外部 URL 场景按需要补充额外检查项。

版本记录展示检查到的脚本、样式数量及逐项诊断。检查通过后明确确认激活，系统才切换该环境入口。登记已成功而预检失败时，保留原版本记录并重试预检；请求结果未知时先刷新核对，不更换版本号反复登记。

## 就绪检查与访问范围

接入面板中的“接入检查”分别显示应用启用、当前环境版本或宿主模块、可访问页面和具体访问范围的状态。未选择租户、组织、角色时，不会把应用标为所有用户均可访问。ESM 还会核对当前宿主真正包含的入口，避免只凭后端登记值误判。

“访问范围”中依次选择租户、组织和普通角色，再确认需要开放的菜单。默认只选当前应用首页。确认后在同一事务中追加本应用及所选菜单的租户、组织、角色授权，保留现有其他授权。租户和组织的托管管理员继续按既有授权上限同步；`tenant_admin`、`org_admin` 由平台维护，不能在此手工编辑。

保存后重新读取指定目标的真实授权链，使用同一个有效入口菜单在三层的交集判定；角色没有该组织的有效成员时会提示继续分配角色。这里只配置功能菜单权限，调用业务 API 所需的数据授权、机密客户端和业务服务配置按[独立业务接入](independent-business-delivery.md)继续处理。

接入的步骤和环境保存在应用管理 URL 中，应用卡片可再次打开面板。需要编辑更复杂的菜单时进入菜单管理，返回后继续；成功状态来自实际配置，没有独立的“已完成”标志替代服务端检查。

## 接口与权限

| 接口 | 行为 |
| --- | --- |
| `GET /api/applications/{id}/setup?environment=development` | 检查应用、当前环境版本和菜单；可追加完整 tenantId/organizationId/roleId 检查指定访问范围 |
| `GET /api/applications/{id}/setup/organizations?tenantId=...` | 返回授权配置所需的有效组织树，不返回联系人、位置等管理资料 |
| `POST /api/applications/{id}/setup/access` | 明确提交 tenantId、organizationId、roleId、menuIds，仅追加所选授权 |

读取基础就绪状态需要平台根组织的 `system:application` 权限；查询目标、选择组织和配置访问范围还需要 `system:tenant`、`system:authorization`、`system:role`。组织候选使用窄接口，无需为了授权额外获得组织资料管理权限。

授权会在持锁后及提交前复验权限、会话和目标有效状态，审计失败会回滚所有添加。写入期间禁止关闭接入面板、切换环境或目标；客户端晚返回不会更新其他应用或环境。此处的授权只追加，撤销和复杂调整仍使用正式授权管理页面。

接入面板选择的是被检查或发布的环境；实际宿主使用的环境仍由服务端部署配置决定。

## 页面显示

正常运行的微应用直接显示业务内容，移除宿主额外的“令牌已注入”、入口通道与沙箱统计栏，使用侧栏和顶栏之外的可用空间。授权失效、加载失败及运行故障仍显示必要的恢复操作。

## 参考 qiankun 的入口约定

[qiankun 官方 API](https://qiankun.umijs.org/api)通常通过 name、entry、container、activeRule 注册应用；HTML 入口由加载器发现脚本和样式。本平台固定宿主容器、按编码生成挂载路径，并把 HTML 资源清单作为检查结果展示。可信 HTML 加载器原本已使用 `import-html-entry`，默认隔离模式由 iframe 内浏览器加载资源。

这次简化沿用现有入口加载与发布校验，不改变 iframe 的隔离边界。动态资源的路径仍需要构建工具正确配置，参见 [qiankun FAQ](https://github.com/umijs/qiankun/blob/master/docs/faq/README.md)。
