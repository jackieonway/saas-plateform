# 给业务用户配置权限

普通用户访问工单或门店，需要同时具备有效成员关系、应用/菜单权限，以及资源动作的数据授权。

## 配置步骤

1. 确认用户所属租户与当前组织，并建立有效直接成员关系。
2. 在租户、组织的应用授权上限内，为角色配置应用入口、菜单和操作按钮；让用户在当前组织取得角色。
3. 在平台数据授权页面选取当前组织的有效成员与目标应用。
4. 为所需资源/动作选择已经登记的 SELF、ORG、ORG_SUBTREE、TENANT 等合法范围；仍受租户和组织硬上限限制。
5. 预览、保存，再让普通用户刷新授权上下文并实际操作。

父组织角色和菜单可以有既定继承规则，成员上的数据授权不因此自动继承。用户切组织后需重新核对新组织的直接成员授权。分配为工单处理人或门店负责人，不自动成为所有记录的 owner。

## 验证和排错

- 应用不可见：检查租户/组织应用授权、角色菜单及入口路径。
- 按钮可见但 403：检查对应 resource/action 数据授权及服务端策略。
- 详情 404：可能不存在，也可能不在当前可见范围。
- 管理保存 409：读取新版本并重新预览；结果未知时先查询。
- 成员目录为空：检查目标组织、当前有效成员和 memberLookups 声明。

授权撤销后重新发起业务请求验证，不能用仍留在页面上的旧结果判断撤销失败。管理 API 和服务端策略见 [数据授权管理](data-grant-management.md)。
