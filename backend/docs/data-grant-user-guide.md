# 数据授权使用指南

数据授权页面用于维护某个直接成员在某个应用中的业务数据范围。页面来自 `frontend/src/pages/system/data-grants/DataGrantsPage.tsx`，保存流程来自同目录 `useGrantEditor.ts`，后端协议见[独立数据授权管理接口](data-grant-management.md)。

## 开始前

登录平台后，在系统管理中进入“数据授权”页面。需要 `system:data-grant:read` 查询权限；修改还需要 `system:data-grant:write`、实际平台租户根组织上下文以及目标可写的服务端管理边界。非平台根上下文只能在允许范围内只读查看。按钮是否出现不是最终授权依据，保存时后端会再次核验。

目标成员必须具有有效的直接组织成员关系，目标应用启用，且租户和目标组织都已授权该应用。运维还需在平台启动配置 `DATA_GRANT_POLICY` 中登记应用能力和管理范围。页面不会列出策略外目标，也不接受手填成员 ID 来绕过发现接口。

菜单和按钮权限决定“能做什么”，数据授权决定“对哪些数据做”。给成员增加数据授权不会自动增加其角色、菜单或按钮权限；继承祖先组织角色也不会继承另一个成员的数据授权。

## 选择目标

1. 在“目标应用”中明确选择应用。页面不会自动选第一项。
2. 按姓名或账号搜索，查看成员卡片中的租户和组织。页面每页显示 10 项，可以翻页。
3. 点击目标成员卡片。系统重新读取这个成员与应用的实时快照；同一个用户属于不同组织时，对应不同直接成员，应分别核对。
4. 查看标题中的成员、租户、组织、应用和直接成员 ID。每次切换目标都会清除上一个目标的草稿和预览。

从用户管理进入时，页面可携带 `userId` 筛选；应用链接可携带 `applicationId`。无效筛选或超出可见范围的应用会显示错误，不会替换成其他目标继续保存。

## 读取和编辑范围

每个资源动作显示当前配置及实际生效的组织硬边界。“无授权”表示默认拒绝。只能选择服务器明确允许的 scope：

| 选项 | 使用含义 |
| --- | --- |
| `SELF · 本人` | 本人的业务记录，同时受组织边界限制 |
| `ORG · 当前组织` | 目标成员所在组织的数据 |
| `ORG_SUBTREE · 当前组织及下级` | 目标有效组织子树的数据 |
| `TENANT · 租户（仍受组织边界限制）` | 配置租户范围，实际效果继续与组织硬边界相交 |

除目标位于平台租户根组织外，`TENANT` 实际会收窄为 `ORG_SUBTREE`。展开“组织硬边界”查看具体组织 ID；不能只按 scope 名称判断可访问范围。

修改下拉选项生成差量，选择无授权会生成撤销项。未改动的授权保持原值。已存授权若已不在当前可管理能力中，页面会展示其状态；处理这种情况应先核对服务端能力登记，不能通过直接改数据库绕过约束。

## 预览后保存

1. 编辑本次需要调整的资源动作。
2. 执行预览，检查“新增”“修改”“撤销”、变更前后完整列表、实际范围及组织数量。
3. 可展开“查看精确提交内容”，核对 target、版本和差量。
4. 点击“确认保存”。页面提交刚刚审阅的同一份差量和版本。
5. 等待“授权已保存”回执，记录请求编号；有审计权限时可点击“查询本次审计”。

继续编辑会立即使旧预览失效，需要再次预览。预览不会锁住版本，其他管理员可能同时修改。服务端接口本身允许直接 PATCH，管理页面采用先预览再保存流程。

成功保存的变更与 `DATA_GRANT_CHANGE` 审计同事务提交。应用下一次受保护的新请求使用当前授权；已经显示的旧数据不会因此自动变成新的授权判断，应用需要重新请求。保存不会给予额外功能权限。

## 处理冲突和不确定结果

| 页面提示或现象 | 后续操作 |
| --- | --- |
| 授权版本已变化 | 点击“重新读取授权”，审阅当前状态，再重新编辑和预览 |
| 保存结果待确认 | 先重新读取实际状态，按请求编号核对审计；不要重复提交旧差量 |
| 写权限或目标范围变化 | 暂停编辑，确认当前组织、独立管理权限和目标边界 |
| 没有可查询成员 | 核对直接成员、账户/租户/组织有效期、两级应用授权、服务端策略 |
| 没有可编辑的资源动作 | 核对 capability 是否登记，以及目标应用有效菜单权限是否登记对应资源动作 |
| 审计记录暂不可确认 | 核对审计查询权限和范围；保存结果以成功回执及重新读取状态为准 |

网络中断或服务端错误后，前端不会自动重试保存。重新读取只证明当前状态，不能单独证明上一次保存成功或失败。需要结合请求编号、审计与实际授权判断。

切换组织、用户、会话或退出登录会使原编辑视图失效，迟到的响应不会用于新身份。应在新上下文重新选目标和读取。接口参数和环境策略的详细约束见[管理接口](data-grant-management.md)。
