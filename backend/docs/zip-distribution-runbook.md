# ZIP 节点分发指南

这是可选应用发布能力：平台安全解包一次，将规范文件和摘要推送到固定节点，各节点独立存储。默认同机 ZIP 模式不需要此功能，基础 Compose 不自动启动节点代理。

## 准备节点组

每个节点按 [节点代理指南](../tools/artifact-agent/README.md)配置本地目录、独立凭据、回环 HTTP 和受控 HTTPS。当前组有 2–8 个必需节点，全部成功才可切换；没有任意请求 URL 或可选节点。

平台设置 ZIP_DISTRIBUTION_CONFIG_FILE，JSON 顶层 groups，每项包含 policy 与 nodes。policy 与节点完整策略一致；nodes 的每项包含 nodeId、caRef、tokenRef，CA 和 token 使用真实绝对私有路径。未设置时维持同机模式。

平台 Compose 若要启用，须明确透传变量并只读挂载私有文件；默认模板不会替操作者选择目标。平台、节点来源使用正常 HTTPS 校验，不跟随重定向或任意代理。publicOrigin 与平台 MICRO_GATEWAY_ORIGIN 一致，同应用同来源的镜像路由与 ZIP 模式不能混管。

## 网关配置

使用 [zip-distribution.conf.example](../nginx/zip-distribution.conf.example)中的 auth_request 门禁和固定节点组，保留真实 TLS、CSP 与来源隔离。按原始 request_uri 检查路径，不重复解码后绕过版本门禁。需要相应 Nginx 模块，修改后先检查配置再明确 reload。

节点 API 仅供平台调用，公共静态入口经网关。各节点不共享源码、Docker socket 或产物卷。

## 发布流程

1. 上传 ZIP，平台完成现有安全解包与不可变内容登记，受管候选保持草稿。
2. 由有权的平台根管理者选择版本和固定组，提交带稳定 requestId 的分发意图；未知提交复用原意图查询。
3. 后台按持久 attempt/nonce/lease 先校验现有内容，只对明确缺失的版本安装，不覆盖冲突目录。
4. 全部必需节点给出新鲜、正确回执后进入就绪；预检/激活/回滚还会重算节点内容、请求真实静态 URL，并在指针事务内复核。
5. 离线、缺文件、错误摘要/CA/token 或策略改变均阻止新切换。超时可重新领取，旧 attempt 不能提交完成。

## 故障与保留

节点正常内容经校验可在重试中复用，损坏内容保持冲突供调查。配置删除不解除历史受管候选门禁，不能借其他环境或编码路径的回执放行。

当前/上一版本的已有静态资源按保留窗口继续提供，新切换仍要重新验证。没有自动删除旧版本的接口。当前已有候选验收不证明物理跨机存储耐久性；生产需要独立验证网络、磁盘、备份和全部节点故障恢复。
