# 生产配置与启动安全

本文件说明 Phase 12 的平台后端运行约束。实际准生产部署、HTTPS 和备份恢复结果以阶段验收报告为准。

## 环境文件与生产模式

- `APP_ENV=production` 或 `APPLICATION_ENVIRONMENT=production` 任一个成立，平台即执行生产检查；另一个变量不能将其降级为开发模式。
- `APP_ENV` 只接受 `development`、`test`、`production`。部署明确设置两个环境变量为 `production`。
- 操作系统／服务管理器已经设置的值优先于环境文件。生产不自动搜索 `.env`，包括父目录。
- 要读取环境文件，明确设置绝对路径 `DANTE_ENV_FILE`。文件需在 Git 忽略目录，限制读取权限。已设置的服务变量不会被文件覆盖。
- 开发模式只加载工作目录自己的 `.env`。该文件不能隐式启用生产模式；生产应使用服务变量或明确指定文件。
- 配置检查发生在数据库连接之前。错误只说明配置键和要求，不回显密钥、连接串或文件内容；Config 没有 Debug 实现。

## 必需配置

| 配置 | 生产要求 |
| --- | --- |
| `DATABASE_URL` | 显式 PostgreSQL 连接串，平台库与业务库独立；通过私有环境配置传入 |
| `JWT_SECRET` | 至少 32 字节的随机密钥，拒绝仓库默认值、占位词、重复值及空白／控制字符；仅平台持有 |
| `METRICS_TOKEN` | 独立于 JWT 的 32～256 字节随机 URL 安全令牌；只用于运维指标接口 |
| `PUBLIC_APP_URL` | 一个精确 HTTPS origin，如 `https://saas.example.com`，不含路径、查询或账号密码 |
| `MICRO_GATEWAY_ORIGIN` | 一个精确 HTTPS origin，默认继承 `PUBLIC_APP_URL` |
| `MICRO_ALLOWED_ORIGINS` | 逗号分隔的精确 HTTPS origin，默认只有网关；每次预检重定向都重新检查 |
| `CORS_ALLOWED_ORIGINS` | 逗号分隔的精确 HTTPS origin，默认只有宿主公共 origin；禁止 `*` 和 `null` |
| `TRUSTED_PROXY_IPS` | 可选、逗号分隔的精确代理 IP，不支持通配或 CIDR；原生单机网关可明确填写 `127.0.0.1,::1` |
| `MICRO_CA_CERT_FILE` | 可选、额外 CA 的绝对 PEM 路径；启动解析，正常证书／主机名检查保持启用 |

平台 CORS 只开放必要方法、Authorization、Content-Type、X-Request-Id，不开放 cookie 凭据。opaque iframe 的 `Origin:null` 仅属于独立工单业务 API 的既有 Bearer 接入契约，不属于平台 CORS 来源。

运行时 TTL 不能为负数、零或格式错误：session 1～720 小时，登录票据 1～60 分钟，普通 access token 1～86400 秒，refresh token 1～7776000 秒。应用令牌仍受既有每应用受众、最多 5 分钟及每请求内省契约约束。JWT 不接受过期宽限，`exp <= 当前时间` 即拒绝。

## 首次初始化与存量升级

空用户表的生产首次初始化需要显式 `BOOTSTRAP_ADMIN_USERNAME` 和 `BOOTSTRAP_ADMIN_PASSWORD`。密码至少 12 个字符且不能使用已知演示密码。事务仅建立平台租户、根组织、核心 system／hermes 应用、管理菜单和一个平台管理员。

生产运行期间的用户创建、管理员重置和个人改密同样使用统一检查：至少 12 个字符，最多 1024 字节，不能使用已知演示密码、控制字符或纯空白。失败检查发生在密码哈希、写入与会话撤销前；合法改密／重置仍按既有规则立即撤销对应用户会话。开发模式保留原来的至少 6 字节规则。

历史迁移包含微应用示例。首次生产初始化只禁用这些确切的示例应用及已知演示密钥客户端，保留记录，不授予示例应用。历史迁移本身不修改。

用户已经存在的数据库不会再次建立管理员，不会根据环境变量重置密码或改写授权。启动前只读检测启用账户的六个已知演示密码，以及启用客户端的六个已知演示密钥哈希；修改用户名／client_id 也不能避开检测。发现后拒绝启动，由管理员显式轮换或停用，再重新部署。检测不会删除／修改账户、客户端或授权。

密码检测逐批读取启用账户，并使用原 Argon2 校验；时间随账户数及密码哈希参数增长。大量账户安装需在发布窗口预先执行和测量该检查。它用于拒绝仓库中已知凭据，不是对所有用户密码强度的推测。

`AUTO_CREATE_DATABASE` 默认关闭；得到建库权限的首次部署可以明确开启，仅在目标库不存在时创建，再执行增量迁移。连接或迁移失败时启动停止，不监听 API；失败迁移先按恢复手册处理，再重新启动。

## 内省限流与代理身份

OAuth 客户端注册表、密钥轮换及全局令牌／设备码管理属于平台资源。对应管理 API 同时要求平台上下文及 `system:oauth` 功能权限；普通租户即使获授该菜单／权限也不能管理这些全局资源。个人会话操作和应用令牌签发／内省仍沿用各自已确认的授权契约。

平台每个请求先根据实际 TCP 对端规范客户端 IP。只有 `TRUSTED_PROXY_IPS` 中的对端可以提供代理 IP。网关必须覆盖 X-Real-IP 和 X-Forwarded-For，后端端口只暴露给网关／受信网络，不能让外部请求直接冒充可信代理。

内省端点按如下顺序保护：

| 保护 | 配置／默认值 | 行为 |
| --- | --- | --- |
| 每 IP 总请求上限 | `OAUTH_INTROSPECTION_ATTEMPTS_PER_MINUTE=3000` | 所有尝试在认证查询前计入，超限 429 |
| 同时认证查询 | 固定 32 个进程内槽位 | 槽位用尽立即 429，不无限排队查询数据库 |
| 认证失败预算 | `OAUTH_AUTH_FAILURE_REQUESTS_PER_MINUTE=30` | 错误／无机密客户端凭据计入失败预算，超限 429；不占用合法客户端的独立配额 |
| 已认证客户端配额 | `OAUTH_INTROSPECTION_CLIENT_REQUESTS_PER_MINUTE=600` | 根据数据库认证后的 client_id 计数，不能靠修改 IP 或请求 client_id 绕过 |

超限响应提供 Retry-After。内省必须使用启用的 CONFIDENTIAL 客户端和正确密钥；PUBLIC client_id 不构成内省认证。认证／令牌有效性每次读取数据库，限流不会引入授权成功缓存，撤销与停用仍立即生效。普通 token、revoke 和 device 端点保留既有 30 次／分钟保护。

全部限流为进程内、单实例配额，使用单调时钟；身份表有上限，锁异常或饱和时拒绝请求。多实例部署还需要网关共享限流。多个应用服务共用出口时应按实际负载调整总请求上限与客户端配额，并实测被拒绝时的重试行为，不能把关闭限流当作容量优化。

## 留存、观测与退出

- `OAUTH_AUTO_PURGE=false` 为默认值：启动和后台任务不自动删除历史 OAuth 数据。设备码的过期状态更新只改状态，不删除记录。
- 现有管理员手动 purge 接口是明确且有审计的运维操作；使用前确认留存和恢复口径。工单、通知、审计和平台会话不自动清理。
- 生产日志采用 JSON；请求 ID、受限路由标签和已验证身份归属用于定位问题，不记录请求正文、查询参数、密码、令牌或机密客户端密钥。
- 平台内部失败使用固定错误码，不能将数据库／网络错误链直接返回或写入日志。
- 收到 SIGTERM／Ctrl+C 后平台停止接收新请求、完成已有请求并关闭数据库连接池。部署管理器仍应设置合理的最终退出时限。
