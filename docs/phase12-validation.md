## 恢复与容量记录

本次备份 CLI 耗时 **6.233 秒**，恢复 CLI 耗时 **10.054 秒**。从启动恢复到轮换签名密钥、服务就绪、重新登录及关键业务/授权检查完成共 **25.940 秒**，低于已确认的 1 小时演练目标。备份点年龄在验收中检查为小于 24 小时；两目标库创建前确认不存在。恢复后重置了 8 个用户的会话版本、撤销 9 个会话和 12 个令牌；旧凭据在旧密钥和新密钥下均被拒绝。恢复数据中的租户授权、通知、发布、迁移和软删除工单得到复核；业务服务仍可创建、修改、导出并投递实时提醒。

本机容量探针以 4 并发请求执行 40 次授权工单读取，实测约 **3.70 请求/秒**、p50 **733 ms**、p95 **2138 ms**。35 次错误客户端认证中 30 次收到 401、5 次触发 429，合法客户端仍可读取。此结果受本机 WSL/PostgreSQL TCP 分段环境影响，只用于记录本次拒绝行为和实际耗时，不能外推现网容量或商业 SLA。

## 安全与运维交付

- `docs/production-security.md` 说明 production 环境、显式管理员/随机密钥、演示凭据检测、精确 HTTPS/CORS 来源、可信代理、严格过期与内省配额。平台密钥只保存在平台运行配置中。
- `deploy/native/` 提供干净构建、Nginx/Caddy 生成器、服务模板和迁移失败停止/发布回滚步骤。网关拒绝公共指标和内部路由；默认 CSP 禁止 `unsafe-eval`，仅经显式选择才放宽可信 HTML 应用。
- `docs/observability.md` 与 `deploy/monitoring/` 定义固定标签指标、请求 ID/审计关联、私有 scrape 和本地连续故障告警。故障演练没有向外部接收人发送消息。
- `docs/backup-recovery.md` 与 `deploy/recovery/` 提供双库停写、AES-256-GCM 备份、完整性检查、默认新库恢复、认证重置及每日调度模板。测试没有自动删除业务或审计历史。
- `.github/workflows/production-build.yml` 配置 Node 24/Rust 1.99 的检查、隔离 PostgreSQL 安全测试、干净 release 构建和产物上传。工作流文件和相同的本地门禁已核对；尚无 GitHub runner 执行记录。

## 边界与后续部署
