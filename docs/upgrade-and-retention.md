## 支持矩阵与扩展窗口

| 部署单元 | 起点 | 目标 | 数据兼容边界 |
| --- | --- | --- | --- |
| 平台 | SQLx 0001–0003，checksum 与现有文件相符 | 0001–0004 | 只新增发布操作表及索引；逐表保持旧 UUID、身份、菜单和数据 grants，旧迁移记录保持原字节 |
| 工单 | 已验收 Node SHA256 历史、SQLx v1/v2、兼容混合前缀 | 当前 v3 | 复用严格 catalog/历史验证，保持 UUID、编号计数、创建 receipt 和提醒 intent；不改旧 SQL 或校验值 |
| 工单 | 当前 v3 | 当前 v3 再启动 | 幂等校验，不重复编号或接管未知 schema |
| 门店 | 空的独立业务库 | 当前 v1 | 初始化后再次启动，校验不可变迁移与 schema，拒绝漂移 |
| 旧宿主发布适配器 | 冻结 Phase30 `applications.ts` | 当前平台 API | 实际 HTTP 登记、发布列表和部署列表；精确文件 SHA256 随测试保存 |
| 工单/门店前端 | 精确冻结 Phase30 client/domain/SDK 字节 | 本阶段后端 | 实际三库及独立 Rust 服务：创建、更新、列表和工单幂等重放；逐文件 SHA256 可追溯 |

未知/脏迁移、checksum 不匹配、未知 schema 均停止启动，不用自动修 checksum 通过升级。工单迁移只连接本业务库；业务服务不读取平台身份表。迁移账号所需权限与运行账号边界遵循各项目原有部署说明。

本阶段只实施 **expand**：迁移 0004 不删列、不改旧端点及响应字段，不收缩旧适配器契约。旧页面允许在隔离候选验证期间继续调用这些旧端点；完整浏览器版本和生产最长存活时间仍是 Q08 待确认项，不能据此宣布某个天数后自动 contract。后续 contract 必须另行明确旧版本清单、产品窗口、观测及下线证明，并单独验收。

发布顺序：先备份并验证恢复路径，在隔离库跑支持矩阵，再执行数据库扩展，部署所有新平台实例。滚动升级时旧实例仍能使用扩展后的 schema，但不能登记新在途保护；切换完成前须停止清理评估，排空旧 writer 与外部 CI，核实所有发布任务结束。外部 CI 不在该表的权威库存内。即使全新实例，本预览也不授权删除。

数据库回退不执行 down migration：保留 0004，让旧平台实例读取旧表/端点即可；旧 SQLx 迁移器可能拒绝数据库含新迁移，故**禁止未经验证直接重启旧 ELF 自动迁移**。服务回退需事先验证迁移器策略，或回到经恢复验收的备份副本。静态版本回退通过原有 rollback API 重新预检并交换 active/previous；数据库恢复与静态回退是两个流程。

## 分类政策

以下是隔离环境候选，不代表生产政策获批；各分类实际 purge 均不可用。

| 分类 | 隔离候选 | 生产待确认项 | 本次行为 |
| --- | --- | --- | --- |
| 静态版本/ZIP | 至少 30 天 **或** 各应用各环境最近 5 个不同版本，保护集合取并集 | 缓存/旧页最长生命周期、跨环境外部发布库存、镜像存储所有权 | 唯一 dry-run 试点；只给目标、数量与原因，人工审阅不等于可删 |
| 在线审计 | 180 天 | 合规、调查冻结、导出归档与检索要求 | 不查询受影响明细，不 apply |
| 普通通知 | 90 天 | 已读/未读、业务通知、幂等去重与提醒 intent 的关系 | 不 purge；去重记录不能因通知 TTL 丢失 |
| 业务软删除 | 30 天 | 引用、恢复窗口、租户退出及业务所有权 | 工单/门店均不 apply |
| 会话及 refresh/access token 历史 | 未确定 | 过期凭据缓冲、撤销、重放/异常调查窗口 | UNKNOWN，禁止自动 apply |
| 创建幂等 receipt、提醒 intent、编号计数、发布审计/操作记录 | 未确定 | 重试期限、审计和领域关系 | 不用通用 TTL 删除 |
| 用户/租户等身份软删除 | 未确定 | 法律留存、撤销、引用与恢复 | 不套用业务软删候选 |

保留策略用于在线存量，备份用于恢复。在线保留 30/90/180 天不能推导备份频率、RPO/RTO、备份销毁周期或法律保留期限。备份/加密/灾难恢复仍遵循独立流程。

## 只读试点

平台根且有 `system:application` 权限时，可调用：

```text
GET /api/applications/{uuid}/releases/retention-preview?minimumAgeDays=30&keepLatest=5
saas-platform-admin retention-preview --app-code work-orders --minimum-age-days 30 --keep-latest 5
saas-platform-admin retention-preview --app-code stores --minimum-age-days 60 --keep-latest 8
```

CLI 从 `PLATFORM_API_ORIGIN` 和 `PLATFORM_ADMIN_BEARER` 读取现有受控凭据，通过验证证书的 HTTPS 读取。仅隔离开发允许 `--environment development --allow-loopback-http`。命令不接受 `--apply`；这些保留参数不能用于其他命令，天数范围 30–3650、最近版本数 5–1000。默认就是读取实际引用，不输出假离线计划。API 不提供 POST/DELETE/apply；未知 query 字段被拒绝。

预览返回选定应用的全部已登记环境，始终读取全局引用库存；CLI 的 `--environment` 继续约束既有环境/开发传输选项，不对保留库存按环境切片。

平台用只读 REPEATABLE READ 事务读取全局引用及数据库时钟，然后在阻塞线程池计算，只返回选定应用的安全标识。全局超过 5000 条或输出超过 1 MiB 时拒绝，不能截断后遗漏引用。CLI 严格校验数量、UUID、原因白名单并去除服务器额外字段，不展示路径、原始资源 URL 或凭据。

`PROTECTED` 原因包括 active、previous、跨环境版本、共享 URL/digest、保留期、最近版本、未来时间、外部所有权及在途任务。没有原因的条目也只标为 `MANUAL_REVIEW`，始终返回 `applyAvailable:false`、`deletionPermitted:false`。外部 URL/镜像一律保守保护，平台不拥有 registry 的删除权。

登记、上传、预检、激活和回滚均先写应用范围的持久操作保护，之后释放连接再执行远程 HTTP，可证明结果已确定时只移除本次 UUID 对应的保护记录，并验证影响一行。该表只保存未完成的操作保护，不作为历史表；正常操作生命周期释放保护不属于保留策略 purge。这样明确审计拒绝时，原有业务表和审计表连同该保护表的最终数据仍保持不变。取消/进程退出、依赖不可用、数据库传输失败或明确结果未知时，会保留未完成的保护记录，没有自动 TTL。实例切换、外部任务和孤儿记录须人工核对真实任务及审计后由单独受控运维流程处理；本阶段没有自动 reconcile/批量删除入口。保护释放失败时保守保留记录，调用者仍需按既有未知结果协议读取实际发布状态再重试。

旧镜像资源必须通过实际 HTTP URL 请求校验状态和字节，镜像仍在 registry 不足以证明在线；ZIP 目录另行逐文件校验。预览结果有时点性，不作为后续删除凭据；未来若实现 apply，必须重读引用、建立排他/任务协调，并重新审批生产政策。
