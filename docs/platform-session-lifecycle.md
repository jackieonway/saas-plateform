# 平台会话有效性与撤销（Phase 4）

## 生效规则

- 登录票据 `credential` 带 `ver`，由当前 `users.session_version` 签发；只用于选择组织，10 分钟过期。密码修改、管理员重置或踢出后，版本提升，旧票据立即失效。
- 平台 `session` JWT 带 `sid` 和 `ver`。每次受保护请求查询 `platform_sessions`、用户状态、直接成员关系、租户状态及组织祖先链状态，不使用正向缓存。登出、设备撤销、管理员踢出或密码变更后的下一次请求立即拒绝旧令牌。
- 会话绑定一个租户和组织。组织切换在事务内创建新会话并撤销旧会话；同一旧令牌的并发切换只有一次可成功。前端禁止同一页面并发切换，并清除旧组织查询缓存后写入新令牌。
- 不允许仅凭祖先组织成员身份进入子组织；进入直接成员组织后，祖先角色继承按已确认授权规则处理。数据范围不会因角色继承扩大。
- `platform_sessions.expires_at` 取配置 TTL、组织及其祖先最早到期时间、租户到期时间的最早值。到期后延长组织或租户期限不会复活旧会话。
- 删除成员关系、停用用户/租户/组织（含祖先）会通过数据库触发器撤销相关会话。设置更早的组织或租户到期时间会收紧已有会话到期时间。之后恢复启用或重新添加成员也不会复活旧会话。
- 多设备会话独立存在。`POST /api/auth/logout` 只撤销当前设备；`DELETE /api/auth/sessions/{id}` 可撤销本人指定设备；平台管理员的 `/api/oauth/tokens/kick` 撤销目标用户全部平台会话和 OAuth 令牌。

## 数据库与升级

`0014_platform_sessions.sql` 增加 `users.session_version` 和 `platform_sessions`。`0015_platform_session_invalidation.sql` 增加组织祖先有效性函数及成员、用户、租户、组织变更触发器。已执行的 `0001`～`0013` 文件不修改。

旧平台 JWT 没有 `sid/ver`，升级后明确返回 401，用户需要重新登录。迁移不保存旧令牌明文，也不把旧令牌视为永久有效。会话表只保存 ID、用户和上下文、有效期、撤销时间、IP 与 UA；审计记录必要主体和目标会话 ID，不记录 JWT。生产升级前应告知在线用户重新登录，并在隔离副本演练迁移与回滚。回滚需通过新迁移撤销相关触发器和表，不改写已执行迁移。

## 接口与运维

- `GET /api/auth/my-sessions` 保留已有 OAuth `sessions` 字段，并增加最近 100 条 `platformSessions`（`active`、`isCurrent`、租户、组织、签发与到期时间）。
- `DELETE /api/auth/sessions/{id}` 只能操作本人会话；撤销当前设备后，本次请求成功，后续请求返回 401。
- `POST /api/oauth/tokens/kick` 仅平台上下文且有 `system:oauth` 权限可用；响应增加 `platformSessionsRevoked`。
- 前端改密成功后清除本地令牌并跳转登录。登出请求若未得到服务端确认，仍清理本机令牌，并提示“服务端会话撤销未确认”。
- 每请求查库以换取立即失效语义；需监控鉴权查询延迟和数据库连接池。过期会话行的保留期与清理批次待运维策略确定，不能在未确认留存要求前自动删除。

## 验收证据

隔离 PostgreSQL 17.6 已顺序执行 `0014`、`0015`。`backend/src/scope_tests.rs` 的 `platform_session_lifecycle` 通过真实数据库与进程内 Axum 路由覆盖：双设备独立、登出、指定设备撤销、组织切换旧会话失效、非直接成员切换拒绝、改密与旧票据失效、管理员踢出与重置密码、成员移除及重加、组织祖先停用及恢复、组织和租户到期及恢复、用户停用及恢复、旧版 JWT 拒绝。测试夹具清理后无残留测试租户或用户。
