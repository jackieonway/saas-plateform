# Phase 12 交付验收环境与运行目标提案

> 状态：用户已于 2026-10-02 确认“按本机准生产提案验收”，作为 Phase 12 的环境和目标基线。Phase 11 继续实施；本文件不代表已完成准生产部署或最终交付验收。

## 已具备的基础

平台、独立应用发布和通知已有真实 PostgreSQL、HTTP、浏览器与网关测试。工单试点正在完成真实全链路验收。当前机器有 WSL、局部 Rust／Node／Nginx／Caddy 和浏览器测试运行时，没有可用 Docker daemon。

任务台账 Phase 12 要求实际构建、部署、监控、故障及恢复证据；Q3、Q7、Q10 的生产环境、SLO 和数据留存尚未给定。不能用配置文件或已有开发测试替代最终运行验收。

## 推荐验收方式

在本机建立独立的 Linux 准生产验收环境，使用实际构建产物和原生进程运行平台、Nginx HTTPS 网关、通知及工单服务，配套两个隔离 PostgreSQL 数据库和专用凭据。资源放入 Git 忽略的自有目录，测试完成清理自有实例。

该环境验证工程交付，不直接部署现网。TLS 使用专用测试 CA 并明确加载该 CA 验证证书；不以关闭 TLS 验证作为通过。若后续提供生产主机或 Docker runner，则按同一手册另行验证目标平台。

可选方案是由用户提供指定的预发布／生产主机或 Docker runner、域名与证书配置，在该目标执行。密码、客户端密钥和私钥通过本机 Git 忽略的环境文件／安全配置提供，不在聊天或仓库中保存。

## 建议工程目标

| 项目 | 提案 |
| --- | --- |
| 商业 SLA | 本次不承诺可用性百分比；报告实际工程测试结果 |
| 备份 RPO | 24 小时作为演练目标；平台库和工单库每天备份，备份加密 |
| 恢复 RTO | 1 小时作为演练目标；恢复到新隔离数据库，核对业务与授权数据 |
| 发布 | 构建、检查、增量迁移失败即停止；不可变版本发布与上一版本回滚 |
| 安全配置 | production 强制显式密钥／管理员凭据／HTTPS 与精确来源；签名密钥只在平台 |
| 监控 | 请求 ID、服务／数据库／LISTEN／应用健康及可定位指标；实际注入故障验证告警 |
| 容量 | 报告实际测得吞吐与拒绝行为；认证客户端内省配额由配置管理，保护未认证尝试 |
| 留存 | 工单软删除及通知／审计／会话记录不自动清理；先提供配置与运维步骤，正式保留期另确认 |

测试应涵盖两租户、权限撤销、组织切换、通知、CSV 和版本回滚；恢复后再执行关键授权与业务检查。备份／恢复工具以新数据库为默认目标，避免覆盖现有数据。

## 完成口径

若用户选择本机准生产验收，本阶段按照经确认的原生部署目标完成工程交付；验收报告明确没有现网发布，也不把未执行的容器构建当作通过。Docker 配置和 CI 配置仍交付，实际容器运行留给提供 runner 后的验收。

若用户要求指定主机／容器作为最终目标，则该环境必须可用，未执行的部署门禁不能标为完成。环境与目标确认后更新台账，再执行对应演练。
